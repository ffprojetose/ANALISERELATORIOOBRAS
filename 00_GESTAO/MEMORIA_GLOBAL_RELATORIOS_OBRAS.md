# MEMÓRIA GLOBAL — RELATÓRIOS DE OBRAS

Última atualização: 17/08/2026

Status:
ATIVA — leitura obrigatória antes de gerar ou revisar qualquer relatório mensal de obra.

Esta memória registra regras, metodologia, workflow, aprendizados e erros que valem para
QUALQUER obra gerenciada por esta plataforma. Não contém valores ou decisões específicas de
uma obra — exemplos pontuais do Reserva Park aparecem apenas quando explicitamente marcados
como exemplo.

## 1. PRINCÍPIOS GERAIS

- Relatório mensal deve usar mês-calendário completo (ex.: 01/07 a 31/07).
- A data de emissão do relatório pode ser posterior ao fechamento do mês, mas todos os
  indicadores apresentados devem respeitar a data de corte do mês relatado.
- Nunca usar a posição "até hoje" do sistema em um relatório de mês anterior.
- Preservar o histórico já publicado — relatórios emitidos permanecem como referência, mesmo
  que o sistema de planejamento seja recalculado depois.
- Não reescrever um relatório histórico por causa de uma alteração posterior no sistema
  (VOBI ou equivalente).
- Documentação interna de auditoria (divergências, memórias de cálculo, comparativos
  antes×depois) não deve necessariamente aparecer no relatório do cliente — fica registrada
  nos documentos internos de processamento.

## 2. SEPARAÇÃO DOS INDICADORES

Regra crítica: os indicadores abaixo NÃO são equivalentes entre si e nunca devem ser trocados
mantendo a mesma nomenclatura:

- Curva S previsto;
- Curva S realizado;
- Medição;
- Físico-Financeiro;
- Orçado x Realizado;
- posição financeira;
- pagamentos/desembolsos;
- recebimentos;
- fluxo de caixa.

Se uma fonte histórica não puder ser recuperada com segurança:
- não inventar o valor;
- não substituir por um indicador de natureza diferente apenas para preencher a lacuna;
- renomear a seção/indicador conforme a natureza real do dado que está de fato disponível
  (ex.: se não há "Orçado x Realizado" com corte correto, chamar de "posição financeira
  considerada", não de "Orçado x Realizado").

## 3. REGRA DE CORTE TEMPORAL

Para o relatório de um determinado mês:
- todos os dados históricos apresentados precisam respeitar o último dia daquele mês;
- movimentações posteriores ao corte não podem contaminar o relatório;
- a posição atual do sistema só pode ser usada para (a) programação futura ou (b) informação
  explicitamente rotulada como atual — nunca misturada ao fechamento histórico;
- sempre distinguir textualmente "posição atual" de "fechamento histórico".

## 4. REPROGRAMAÇÃO DE CRONOGRAMA

Quando houver reprogramação do cronograma físico-financeiro:
- explicar ao cliente que houve revisão;
- explicar o motivo técnico da revisão;
- informar que foram alteradas datas, durações e distribuição temporal;
- deixar claro se orçamento, escopo, serviços e quantidades foram preservados;
- não esconder a reprogramação;
- não transformar o relatório mensal em uma auditoria extensa do cronograma antigo;
- preservar as versões anteriores internamente (processamento/histórico).

Nunca utilizar expressões como: apagar atraso, zerar atraso, corrigir os números, esquecer o
passado, fazer a curva fechar.

## 5. VOBI — WORKFLOW APÓS ALTERAÇÃO DE PLANEJAMENTO

Após qualquer alteração relevante no Planejamento do sistema:

1. reler o Planejamento;
2. reler a Curva S;
3. reler o Físico-Financeiro;
4. verificar a data final da obra;
5. comparar com o rascunho de relatório atual;
6. identificar somente os indicadores que de fato mudaram;
7. só depois atualizar o relatório.

Nunca reutilizar automaticamente valores extraídos antes da alteração do Planejamento.

## 6. HISTÓRICO x PROGRAMAÇÃO FUTURA

- Dados históricos fechados são preservados, mesmo que o sistema recalcule o previsto depois.
- Programação futura pode ser relida e atualizada a qualquer momento.
- Pequenas mudanças posteriores do sistema não devem alterar silenciosamente medições ou
  relatórios históricos já publicados.
- Divergências posteriores encontradas devem ser registradas internamente (auditoria), não
  corrigidas por conta própria no relatório do cliente.

## 7. RECEBIMENTOS ANTECIPADOS

Quando houver recebimento antecipado:
- manter a data real da entrada do recurso;
- identificar gerencialmente como antecipação do ciclo seguinte, quando aplicável;
- não duplicar esse recebimento no mês seguinte;
- não calcular automaticamente "saldo livre", "lucro" ou "sobra" apenas pela diferença entre
  recebimentos e despesas.

## 8. ANÁLISE POR DISCIPLINA

- Só usar valores financeiros por disciplina se houver fonte compatível com a data de corte
  do relatório.
- Se a posição financeira por disciplina estiver contaminada por período posterior ao corte,
  não utilizar.
- É preferível apresentar uma análise física/operacional confiável do que valores financeiros
  incorretos.
- Nesse caso, usar medição, registros fotográficos e outras evidências comprovadas para
  compor a leitura por disciplina.

## 9. REGISTROS FOTOGRÁFICOS

- Usar somente atividades comprovadas pelos registros.
- Não inferir a execução de um serviço sem evidência fotográfica ou de medição.
- Relacionar cada registro fotográfico com a disciplina e a evolução observada.
- Manter a seção fotográfica antes das conclusões finais do relatório, quando compatível com
  o modelo visual em uso.

## 10. LINGUAGEM DOS RELATÓRIOS

Evitar conclusões não demonstradas pelos dados disponíveis, como:
- "sem sobrecusto";
- "obra sob controle financeiro";
- "financeiro compatível".

Preferir formulações neutras quando os dados não sustentarem uma conclusão mais forte:
- "permanece sob acompanhamento técnico e financeiro contínuo";
- "o orçamento global permanece preservado";
- "os indicadores continuarão sendo monitorados".

## 11. MODELO VISUAL

Para relatórios de uma mesma obra:
- reutilizar a identidade visual do modelo/relatório anterior;
- não redesenhar do zero;
- manter capa, fontes, cores, cabeçalho, rodapé, margens, tabelas e padrão de fotos;
- conteúdo e estrutura técnica (seções, indicadores) podem evoluir de um mês para outro;
- a identidade visual deve permanecer consistente entre os meses.

Regra-resumo: **VISUAL ANTERIOR + ESTRUTURA TÉCNICA ATUAL APROVADA.**

## 12. WORKFLOW PADRÃO PARA RELATÓRIO MENSAL

1. ler a memória global (este arquivo);
2. ler a memória específica da obra;
3. localizar o último relatório aprovado;
4. definir a data de corte do mês a relatar;
5. conferir o Planejamento;
6. extrair a Curva S;
7. extrair o Físico-Financeiro;
8. extrair a Medição;
9. levantar o financeiro com o corte correto;
10. levantar os recebimentos;
11. verificar antecipações;
12. analisar as fotografias;
13. validar os indicadores entre si (coerência Curva S x Físico-Financeiro x Medição);
14. redigir/atualizar o Markdown do relatório;
15. revisão humana;
16. gerar DOCX no modelo visual existente;
17. validar visualmente o DOCX gerado;
18. gerar PDF;
19. registrar checkpoint no GitHub (apenas arquivos de plataforma, nunca dados de obra —
    ver `.gitignore`).

## 13. ERROS E ARMADILHAS JÁ IDENTIFICADOS

- Usar a posição atual do sistema em um relatório histórico.
- Misturar pagamentos com Orçado x Realizado.
- Misturar Medição com financeiro (são grandezas diferentes: medição de produção x custo
  lançado).
- Usar dado de um mês posterior no relatório do mês corrente (ex.: dado de agosto no
  relatório de julho).
- Reescrever o histórico depois de uma reprogramação.
- Utilizar uma quebra por disciplina contaminada por período posterior ao corte.
- Calcular saldo de caixa quando existe recebimento antecipado misturado ao período.
- Corrigir diferenças por rateio manual sem evidência/fonte.
- Apagar ou remover auditorias antigas.
- Gerar o documento final em um layout diferente do usado na série anterior da mesma obra.
- Usar valores de programação futura sem reler o sistema após uma alteração no Planejamento.

## 14. HIERARQUIA DAS FONTES

Ordem de prioridade ao buscar um dado:

1. relatório/documento histórico já fechado na data correta;
2. exportação do sistema com filtro/corte comprovado;
3. Medição oficial;
4. Curva S / Físico-Financeiro vigente, para fins de planejamento;
5. registros fotográficos;
6. posição atual do sistema — apenas quando pertinente (programação futura ou informação
   explicitamente rotulada como atual).
